# 资源额度控制

管理后台 → 系统设置 → **资源额度**，可查看本项目的计数、修改阈值和执行分批清理。GET 删除、删除链接和访问统计默认开启，原有接口路径不变。图片仍使用现有 `/rest/图片Key` 地址。

## 上线顺序

1. 部署新代码前，对已完成 `0001`～`0011` 的数据库执行迁移（会新增 `0012_resource_limits.sql`）：

   ```powershell
   npx wrangler d1 migrations apply picx-db --remote --config wrangler.local.jsonc
   ```

2. 部署代码，检查 `/rest/settings/resource-config` 返回上传边界。
3. 登录后台，进入系统设置，确认原有图片的用量和阈值。迁移从 D1 图片记录初始化用量，保留现有图片、用户和统计。

`wrangler.local.jsonc` 包含账户专用数据库配置，仍应仅保存在本机。迁移不是幂等 SQL 文件，使用 Wrangler 迁移管理器执行，不要反复手工执行 SQL。

## 默认阈值

| 配置 | 默认值 |
| --- | --- |
| 单张 / 单批大小 | 20 MiB / 40 MiB |
| 每批张数 | 5（后台可下调） |
| 每日上传预算 | 500 次、500 MiB |
| R2 总存储预算 | 8,000,000,000 字节，即十进制 8 GB |
| 用户容量 | 执行用户管理中的配额；0 表示不设用户上限，仍受全站预算约束 |
| 删除链接 | 开启，仍使用 KV |
| 新删除链接有效期 | 0 天，即保留原有永久链接行为；可改成正整数天 |
| 图片访问统计 | 开启，10% 采样，每日最多 5,000 条记录 |
| 统计明细 / 操作日志保留 | 30 天 / 90 天 |
| 每批 / 每日历史清理预算 | 100 / 6,000 行 |
| 每日 KV Token 清理预算 | 500 次，超出后排队 |
| API Key 最近使用时间 | 最多每小时更新一次 |
| 普通 API / 图片入口 | 每 IP、每实例每分钟 120 / 600 次 |
| 登录 / 删除入口 | 每 IP、每实例每分钟 10 / 30 次 |
| API Key 入口 | 每 Key、每实例每分钟 120 次 |

原有上传接口每实例每 IP 每分钟 10 次、列表 30 次的限流继续生效。所有每日预算于 **00:00 UTC（北京时间 08:00）**重置。阈值保存于 D1 的 `system_settings.resource_limits`，读取缓存最多 30 秒；数据库触发器直接读取最新的存储和上传预算。

## 计数含义

- 预算计数是应用自己的控制值，不是 Cloudflare 账单、剩余免费额度或精确 SQL 写入行数。
- 每次上传尝试先在数据库中原子预留容量；整批预留失败时整批回滚，还没写 R2/KV。多个实例同时上传也共享这组存储和每日预算。
- 预留成功后，即使上传失败、删除图片，也**不返还每日次数和字节预算**，因为失败尝试可能已经消耗过 R2、KV 操作。这能防止反复上传删除绕过每日预算。
- 重新命名需要临时复制文件，因此也预留临时存储容量，并消耗一次每日预算；目录创建消耗一次零字节预算。接近容量上限时，重命名可能因临时空间不足被拒绝。
- 用户配额统计包含 R2、HF 和未完成上传，R2 全站存储预算只统计 R2。
- 图片数据库记录仍使用原有异步登记方式。登记失败时，R2 文件继续由预留记录占用容量，防止漏记后越传越多。
- 只有物理删除成功后，才删除数据库记录并释放存储计数。旧图片的 KV 删除 Token 会从 R2 元数据读取后清理；新图片额外在 D1 保存 Token，正常后台删除时也会清理 KV。
- KV 清理超过每日预算或失败时，Token 留在 D1 队列等待后续上传/手工清理处理，图片删除继续完成。删除链接会验证当前图片的 Token，旧的待清理链接不能删除后来重用同一 Key 的新图片。
- “核对一小时前的预留”每次最多检查 5 个旧预留。确认存储没有文件才释放；有文件的预留保留，不会因超时自动释放容量或擅自删除文件。

## 客户端与接口

- 网页可以多选许多图片，上传时按当前数量和字节上限自动串行分批。失败时展示已经成功的图片，剩余文件保留；不会自动重复上传成功批次。
- 后端检查真实请求体长度、每张大小、整批大小和数量，不依赖浏览器检查或客户端声明的 `Content-Length`。
- `POST /rest/upload` 仍使用 `files` 等原有字段，返回原有 `code/msg/data` 结构；超限返回 413 或 429，并给出原因。
- 外部调用方需自行分批上传。`GET /rest/settings/resource-config` 公开返回 `maxFileBytes/maxBatchFiles/maxBatchBytes/deletionLinksEnabled`。
- 批量 DELETE 每批也最多 `maxBatchFiles` 个 Key；网页会自动分批。原 `GET /rest/del/:key` 删除接口继续默认公开启用。
- 关闭“删除链接”会暂停 `/rest/delInfo/:token`、`/rest/delImage/:token`，并停止给新上传写 KV Token。原有 KV 记录保留，重新开启后仍可使用，后台删除及 GET 删除不受该开关影响。
- 修改删除链接有效期只作用于新写入/重命名更新的 Token，不会扫描重写已有 KV 数据。
- 管理员设置接口：`GET/POST /rest/settings/resources`；分批清理：`POST /rest/settings/resources/cleanup`；预留核对：`POST /rest/settings/resources/reconcile`。均要求管理员认证。

## 访问统计和历史清理

统计采样在写数据库前进行。达到每日记录预算后，不再增加统计明细和图片访问计数，仍返回图片。后台访问次数和趋势是**实际采样记录数量**，不会伪装成完整访问量或放大成估算总量。

每个运行实例在上传或访问图片后最多每十分钟尝试一批历史清理，全站共用每日清理预算；也可在后台手工清理。先找出最多 100 个过期候选，再预留删除预算；没有过期记录不消耗清理行数预算。并发时重复候选或删除失败可能保守多计，不会返还预算。没有访问/上传时不会运行定时任务；需要固定时间清理时可另外配置受保护的调度。

新图片路径最多 512 个 UTF-8 字节。访问统计保存的 Referer / User-Agent / 国家 / 城市分别最多 512 / 256 / 8 / 64 个 UTF-8 字节，避免请求头过长快速占满 D1。

## 保护边界

这些阀门约束经过本项目的操作。账户中的其他 Worker、其他 R2 桶、控制台/S3 手工上传等不受它们约束。初始容量以 D1 已登记图片为准；已有未登记 R2 文件应先核对，不能把后台计数当成整个账户的真实 R2 存储量。

入口限流是实例内的轻量保护，不是全网严格限流；请求被应用拒绝时仍可能消耗 Functions 请求额度。可另外在自己的 Cloudflare 域名配置 WAF 限流，并检查 `pages.dev` 等备用入口。这里不自动修改域名规则，不承诺账户级零费用或绝不触达平台额度。

## 验证

```powershell
npm install
npm run test:resources
npm run build
npx wrangler pages functions build --outdir .wrangler/compiled-functions
```

测试要求 Node.js 22.13 或更新版本，使用内存 SQLite 和存储故障模拟，不连接正式 R2、KV、D1。另可使用 Wrangler `--local` 检查真实 D1 运行时的迁移。
